# Anti-generated UI rules

Multiverse should feel authored around real agent work and verifiable outcomes, not assembled from familiar AI-product decoration. Apply these rules to every user-facing screen.

## Product meaning first

- Every section must help a person define a task, observe execution, review evidence, decide on a permission, compare outcomes, or manage reusable knowledge.
- Write about the person's material and next decision. Never expose design-system implementation notes, spacing demonstrations, token names, or component inventories in product copy.
- Avoid generic SaaS language such as "seamless," "effortless," "magic," "smart," and "all-in-one" unless a concrete claim immediately explains it.
- Do not publish generic readiness labels such as "Ready" or "All systems ready" unless they report a real, current system state.

## Visual restraint

- Do not use sparkles, brains, robots, magic wands, glowing nodes, or agent avatars as shorthand for AI. Choose a task-specific icon such as terminal, branch, check, shield, history, tool, document, or arrow.
- Do not add randomized decorative marks, floating dots, orbit lines, abstract geometry, or JavaScript-generated ornament.
- Decorative motifs must belong to the Multiverse identity, use deterministic placement, and support hierarchy rather than fill empty space.
- Avoid generic glass cards, luminous gradients, neon glows, oversized radii, nested metric cards, and pill-shaped controls as default styling.
- Blur is reserved for functional overlays, media readability, or fixed mobile chrome. It is not a card treatment.

## Interaction restraint

- Feedback must explain a real state change. Do not generate encouragement, synthetic activity, rotating slogans, or decorative notifications.
- Animation supports orientation, focus, or continuity. It never exists only to make the interface appear intelligent.
- Empty and loading states describe what is happening and what the person can do next; they do not claim the system is thinking without a real process.

## Review test

Before shipping, remove any element that could be placed unchanged into an unrelated AI landing page. Keep only product-specific content, Multiverse identity cues, real state, and controls tied to a clear task.
